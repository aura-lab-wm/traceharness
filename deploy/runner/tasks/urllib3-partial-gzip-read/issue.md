# urllib3: preserve decoded bytes after a partial read

Upstream issue: https://github.com/urllib3/urllib3/issues/3636
Upstream merged fix: https://github.com/urllib3/urllib3/pull/4960
Baseline revision: 98a60f9c26a4d64cf18c7e004b9adda4303bc28c

A compressed HTTPResponse can lose already-decoded bytes when a bounded read is followed by read() without an amount. Repair the decoded-buffer handoff so concatenating the partial and remaining reads reproduces the entire original payload exactly. Preserve ordinary uncompressed and raw compressed reads, EOF behavior and full-read caching.

This is a real upstream issue packaged as a curated TraceHarness repair task, not a general benchmark or unrestricted repository-editing claim. Python 3.12 and the existing pinned dependencies suffice. All checks operate offline; no service, TLS connection, model key or credential file is needed. Both public and hidden checks verify that the imported package lives inside this exact candidate checkout.

Preserve all original files except the one documented editable module; comments and formatting in that module may change, but unrelated AST changes are rejected. The protected src/urllib3/_version.py is deterministic build metadata supplied because upstream Git archives omit the file generated by hatch-vcs. Its 0.0.0+traceharness commit identifier is not an upstream release version. No installed urllib3 source is substituted.

The baseline is the affected revision linked directly in upstream issue #3636, so ordinary public gzip/deflate reads reproduce the failure. Reference validation applies only the exact decoded-buffer insertion from merged fix 54b6f7e to this older revision; it does not replace the entire source file with a later revision. No private buffer state is synthesized by the reproduction.

Public edit contract: Only add one guarded buffer drain immediately after `data = self._decode(data, decode_content, flush_decoder)` in HTTPResponse.read's `if amt is None` branch. The guard must be `decode_content and len(self._decoded_buffer) > 0`, `decode_content and len(self._decoded_buffer) != 0`, or `decode_content and self._decoded_buffer`. The body must either append data with self._decoded_buffer.put(data) then assign data = self._decoded_buffer.get_all(), or assign data = self._decoded_buffer.get_all() + data. Preserve the rest of the entire module AST, including existing caching and partial-read behavior.
